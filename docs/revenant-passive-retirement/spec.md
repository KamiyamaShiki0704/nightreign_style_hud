# 复仇者被动单位释放

来源：2026-09-23 用户要求复仇者被动复用 Summon 已实现的召唤单位内存清理。
仅修改 nightreign_style_hud；Summon 为只读参考。用户于本会话确认以下范围与验收（2026-09-23）。

## 范围与规格

- SPEC-RPR-01：当复仇者击杀触发被动时，应保留现有 15% 概率、10 只上限、60 秒寿命、阵营 47、效果 295000 与出场/退场动画 1830/1840。
- SPEC-RPR-02：当被动生成的单位死亡、寿命到期且现有退场等待结束，或玩家切换离开复仇者时，应停止该单位并请求释放其角色实例；仅释放本被动拥有的单位。
- SPEC-RPR-03：当原生系统仍引用待释放单位或无法验证其释放条件时，不得释放其内存。正常释放应完成角色注销、析构与所属分配器回收，且不能重复释放或清空已被新单位使用的槽位。
- SPEC-RPR-04：当地图加载、世界或玩家切换使原单位归属失效时，不得继续访问旧单位；沿用 Summon 的保留策略，无法安全释放的已脱离对象可保留至进程退出，并记录原因。
- SPEC-RPR-05：当单位完成清理后，应允许后续被动再次生成单位，不得因仅隐藏旧实体而持续占用角色槽位。

## 语义 Probe / 验收

| Case | 前置与输入 | 预期输出与时间边界 |
| --- | --- | --- |
| P01 | 有一只被动生成单位，保持地图有效，等待寿命结束 | 保留 60 秒寿命和现有退场等待；随后出现完整释放记录。原生引用未消失时不设强制释放超时 |
| P02 | 有一只被动生成单位，将其击杀 | 下一次正常更新开始清理；不被更新逻辑复活；每只最多完成一次释放 |
| P03 | 有多只被动生成单位，切换其他角色 | 全部进入清理；家族召唤与普通敌人不被误清理；角色切换后仍能完成释放 |
| P04 | 连续触发被动与清理，至少累计 20 只 | 已完成清理的单位不再占有角色槽位；仍可继续召唤；活动上限保持 10 |
| P05 | 单位活跃或正在清理时传送、退出到菜单或更换玩家 | 清除过期跟踪，不访问旧对象；无法证明安全释放时记录保留原因，不强制调用析构 |
| P06 | 离线提供残留引用、失效读数、改变的原生函数样本 | 拒绝过早释放或未知原生调用；只有引用检查连续两个帧末安静才允许回收 |

自动检查覆盖清理状态、回调分组、原生指纹与分配器协议；编译成功不等于游戏运行通过。
人工最终验收：P01–P05 的动画、游戏稳定性、再次召唤和日志对应关系。
排除模型缓存、子弹内存、家族 Buddy 生命周期、联机全覆盖和其他游戏版本兼容承诺。
